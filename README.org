** About

This project builds two programs: QLogo and Psychi.

*** QLogo

*QLogo* is a compiler/interpreter for the UCBLogo language written in C++ using Qt and LLVM. It mimics very closely the UCBLogo interpreter developed by Brian Harvey, et al. at U.C. Berkeley.

You can find more information about the UCBLogo language by reading the UCBLogo Manual here:

http://people.eecs.berkeley.edu/~bh/usermanual

*** Psychi

*Psychi* is the graphical terminal window for QLogo. It provides a command line, a text editor, and a turtle graphics window.

** To build

At this time I am developing and testing QLogo on the following systems:

- Linux (Fedora 44 using Qt 6.11 and LLVM 22), and
- macOS (Tahoe on Silicon, using LLVM 22 and Qt 6.12 provided by MacPorts), and
- Windows
  - Windows 11 for ARM (although Windows 11 for x86_64 should also work fine)
  - Visual Studio C++
  - LLVM 22.1.8 [if I remember correctly, I installed clang+llvm-22.1.8-aarch64-pc-windows-msvc.tar.xz]
  - Qt 6.11

*** To build in macOS and Windows

I simply use Qt Creator, keep in mind that you likely will have to set some parameters so that CMake can find the required LLVM components.

*** To build in Linux

Make sure you have the required components installed. This would involve using your package manager.

To the best of my memory, you will need the following packages:

- CMake
- Make
- C++ development packages
- Qt6 development packages; your distribution may make some of the components "optional". Make sure you have:
  - The Qt6 SQLite development package
  - The Qt6 SVG development package.
- LLVM development packages, at least version 22.

After you have downloaded the QLogo source code, "cd" into the source directory and issue the following commands.

#+BEGIN_SRC shell
cmake -S . -B build
cd build
make
#+END_SRC

If everything is successful, you should find the built components in the build directory. It's not a good idea to move the items to another location; I don't even know if the "install" script works correctly.

The QLogo interpreter and command-line program will be found at:

~QLogo/build/qlogo/qlogo~

and the graphical user interface with the turtle can be found at:

~QLogo/build/Psychi/Psychi~

** More about QLogo

QLogo aims to imitate, to a great extent, the UCBLogo programming language and user interface. 

** Here are the nuances; they are small (I hope):

*** Colors can be specified in one of five ways (instead of two):

   1. as a palette index (0 to 100), same as UCBLogo

   2. as a list of *three* numbers, one for each of red, green, blue: ~[0 0 0]~ is black, ~[100 100 100]~ is white, also same as UCBLogo.
   
   3. as a list of *four* numbers, similar to Option 2 above, with the fourth value being transparency (or "alpha"). ~100~ is fully opaque, and ~0~ means fully transparent.

   4. as a named color from the X Color Database, e.g. ~white~ or ~lemonchiffon~. The list of color names can be retrieved using the ~ALLCOLORS~ command or from the X Color database found here: https://en.wikipedia.org/wiki/X11_color_names
   
   5. as a hex RGB triplet, preceded by "#", and followed by 3, 6, 9, or 12 hexadecimal digits. For example, each of the following produces the color red: ~#f00~, ~#ff0000~, ~#fff000000~, and ~#ffff00000000~.

*** Changes in font properties (size, color, family) do not affect characters already printed.

This enables multiple colors and fonts on the same console.
  
*** QLogo will look for and automatically load ~startup.lg~ in the user's home directory. It will not search for it in any other path.

*** Garbage collection is on-the-fly.

Memory is freed the moment a word/list/array is no longer needed. ~GC~ and ~.SETSEGMENTSIZE~ are provided for compatibility, but are no-ops.

*** ~SAVEPICT~ saves a copy of the canvas in the format given by the filename's extension.

For example: ~SAVEPICT "MY_PICTURE.PNG~ will save in PNG format.

QLogo can save an image in the following formats: BMP, JPG/JPEG, PNG, PPM, XBM, and XPM

*** ~WINDOW~ no longer simply allows the turtle to run away from the canvas.

~WINDOW~ now grows the canvas to accommodate the turtle's position.

*** There is no facility yet for translation/internationalization.

All the strings used in QLogo source code can be translated, but no translations have been made.

*** QLogo supports Unicode characters.

The ~CHAR~ command takes a Unicode character as a parameter. Similarly, the ~ASCII~ command and ~RAWASCII~ command report the Unicode value of a character.

Unicode values are stored as 16-bit integers. Thus, the maximum value that ~CHAR~ can take is 65535.

Since ASCII is a subset of Unicode, the behavior of ~CHAR~, ~ASCII~ and ~RAWASCII~ are the same as in UCBLogo for ASCII characters.

*** The following commands are not implemented:

**** ~SETMARGINS~:

The original purpose of the command was to enable text to be visible on projectors which cut off outer boundaries of a computer screen. Projectors and monitors produced in recent years show all of the computer screen. In addition, QLogo is a windowed application so an instructor or presenter can move the window to a different position. ~SETMARGINS~ is accepted for compatibility and does nothing.

**** ~FILL~:

One of the user interface principles for QLogo is that the canvas should be device resolution-independent. When the QLogo window is resized or the separator between the text and the graphics is moved then the graphics will be redrawn with the new dimensions. The resulting canvas may have different openings and closures which will cause the flood fill algorithm to draw something completely different. In QLogo, ~FILL~ is accepted for compatibility but does nothing.

**** ~EPSPICT~:

This is replaced by ~SVGPICT~. See ~SVGPICT~ for more information.
**** ~SETLIBLOC~:

Not implemented. QLogo uses a SQLite database to store its standard library. You can use the ~setlibloc~ command line parameter to tell qlogo where to find the SQLite database if it is in a different location than where qlogo expects it.

**** ~SETHELPLOC~:

Not implemented. QLogo uses a SQLite database to store its help text. You can use the ~sethelploc~ command line parameter to tell qlogo where to find the SQLite database if it is in a different location than where qlogo expects it.

**** ~NOREFRESH~ and ~REFRESH~:

QLogo is designed from the ground up to have a very responsive user interface. The canvas will always redraw itself whenever the window is resized. ~REFRESH~ and ~NOREFRESH~ are accepted for compatibility and do nothing.



*** The following variables have no special meaning:

**** ~REDEFP~:

Qt has strong support for internationalization, but in QLogo it is only partially implemented. Internationalization will be supported soon.

**** ~USEALTERNATENAMES~:

Qt has strong support for internationalization, but in QLogo it is only partially implemented. Internationalization will be supported soon.


*** The following commands are NEW:

**** ~SVGPICT~ has been added and is a replacement for ~EPSPICT~.

~SVGPICT~ will save the image on the canvas in Scalable Vector Graphics format.

**** ~ALLFONTS~:

In Psychi it returns a list of all the fonts available on your system. On the command-line interface it outputs the empty list.

**** ~ALLCOLORS~:

Returns a list of all the named colors that QLogo knows about.

**** ~RUNTIME~:

This is mostly for my own curiosity and for debugging. ~RUNTIME~ will take one parameter, a list, which it will execute. A timer will start when the list is executed and then stop when the list is finished. The total running time of the list will be printed. The output will be whatever the list outputs, if anything.

**** ~MARK~:

This is for debugging memory management. ~MARK~ will take one parameter, set a flag on it, and output that parameter. At the moment it is marked, a debugging message will be printed out. Later, if/when the item is deleted, another debugging message will be printed.

**** ~STANDOUT~:

This works in the QLogo GUI by switching the font's foreground and background colors. It isn't implemented for text terminals.

**** ~CLEARTEXT~ / ~CT~:

Clears the Psychi text console. In the command-line interpreter this is a no-op.

**** ~SETBOUNDS~:

The drawing canvas in Psychi is designed to be resolution independent. The user can stretch and resize the GUI window and its components without needing interaction or permission from the QLogo program. Therefore, the best way for the programmer to have control and the GUI to have responsiveness is to set the bounds programmatically. The GUI then can squeeze or stretch the canvas to fit the window as needed.

The coordinate system of the drawing canvas is Cartesian: the Origin ~[0,0]~ is always in the center. The range of the X-coordinate is between ~-boundX~ and ~boundX~. The range of the Y-coordinate is between ~-boundY~ and ~boundY~. For example, a bound set at ~[350 150]~ means that the turtle is visible if its X-coordinate is between -350 and 350 and its Y-coordinate is between -150 and 150. See also ~BOUNDS~.

**** ~BOUNDS~:

Outputs a list of two numbers giving the maximum bounds (x,y) of the canvas. See ~SETBOUNDS~ above for more information.

**** ~FILEDIALOG~:

GUI only. Presents a modal file dialog so the user can select a file. Outputs the chosen path as a word, or the empty list if the user cancels.

**** ~TEMPLOC~:

Outputs the directory ~EDIT~ uses for its temporary file. See ~SETTEMPLOC~.

*** ~FMOUSEPOS~ and ~FCLICKPOS~:

Since QLogo's canvas can have an arbitrary size it is possible that floating point accuracy is required. These two commands are similar to UCBLogo's ~MOUSEPOS~ and ~CLICKPOS~ except that they report their values with floating-point precision.

For compatibility, ~MOUSEPOS~ and ~CLICKPOS~ are provided as library functions.

**** ~:QLOGOVERSION~

A special variable that contains a string composed of the most recent git tag, number of commits since that tag, and the most recent git commit hash.

**** ~:ARGV~:

A special variable that contains a list of every word on the command line used to start qlogo, including the program name. This is similar to ~COMMAND.LINE~ which is the list of words on the command line after a hyphen.

*** The following commands are slightly different:

**** ~LPUT~ and ~FPUT~:

When using the Word form of ~LPUT~ and ~FPUT~, there is no single-character limitation. I'm not sure why that limitation is necessary in UCBLogo.

**** ~CURSOR~ and ~SETCURSOR~:

On the command-line interface ~SETCURSOR~ is a no-op and ~CURSOR~ outputs ~[0 0]~.

**** ~SETTEXTCOLOR~ and ~SETTC~:

On the command-line interface this is a no-op. A parenthesized call with one input changes only the foreground color. Colors use the same five forms as ~SETPENCOLOR~.

**** ~SETTEXTSIZE~, ~TEXTSIZE~, ~INCREASEFONT~, ~DECREASEFONT~, ~SETFONT~, ~SETTEXTFONT~, ~TEXTFONT~ and ~FONT~:

On the command-line interface ~SETTEXTSIZE~, ~INCREASEFONT~, ~DECREASEFONT~, and ~SETFONT~ are no-ops; ~TEXTSIZE~ outputs ~12~ and ~FONT~ outputs the empty word. ~INCREASEFONT~ and ~DECREASEFONT~ change the point size by 2; ~DECREASEFONT~ will not go below 2. ~SETTEXTFONT~ and ~TEXTFONT~ are synonyms for ~SETFONT~ and ~FONT~, respectively.

~SETFONT~ and ~FONT~ apply to the text and edit windows, not the turtle canvas. For the canvas use ~SETLABELFONT~ and ~LABELFONT~.

**** ~OPENWRITE~ character buffers:

As in UCBLogo, ~OPENWRITE~ accepts a list, which names a character buffer. QLogo identifies the buffer by the variable named in the first element rather than by list identity (~.EQ~). After, for example, `OPENWRITE [FOO 200]`, the commands `SETWRITE [FOO]` and `SETWRITE "FOO` have identical meanings.

UCBLogo may use the second list element as the buffer size, but QLogo has no size limit so the size parameter is ignored. So in QLogo these two commands are equivalent:

~OPENWRITE [FOO]~

and

~OPENWRITE [FOO 200]
